# Product

## Register

product

## Users

The primary users are the project owner and other technical developers operating scraper jobs through the local Web UI. They are comfortable with CLI tools, state files, job queues, and scraper parameters, but use the interface to reduce operational friction when monitoring, creating, pausing, resuming, and inspecting jobs.

## Product Purpose

The Web UI exists to make Google Maps scraper operations easier to control and understand without turning the tool into a large platform. Success means a developer can quickly see what is running, what needs attention, what is queued, and what action is safe to take next, including from a mobile viewport used for checking status.

## Brand Personality

Simple, professional, and informative. The interface should feel quiet and capable: direct labels, restrained visual emphasis, compact controls, and enough detail to support confident operation without decoration or ceremony.

## Anti-references

Avoid complicated platform patterns, enterprise BI density, hacker-terminal styling, and generic admin-template sprawl. The UI should not imply a heavyweight SaaS product, command-center theatrics, or analytics-first business intelligence. It should preserve a "less is more" philosophy while remaining useful for technical work.

## Design Principles

1. Prioritize operational clarity: surface job status, queue state, progress, and next actions before secondary metrics.
2. Keep the interface small enough to understand at a glance: add controls only when they remove real operational friction.
3. Support developer confidence: use exact labels, stable layouts, and visible state changes instead of decorative presentation.
4. Make mobile viewing first-class: status, progress, and essential actions must remain readable and usable on narrow screens.
5. Prefer restraint over spectacle: visual design should guide attention without making the tool feel like a platform.

## Accessibility & Inclusion

No special accessibility constraints were specified. The default target is mobile-responsive UI with keyboard-friendly controls, visible focus states, readable contrast, clear status text that does not rely on color alone, and reduced-motion-friendly behavior.
